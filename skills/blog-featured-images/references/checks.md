# Checks and Tests

Every check below exists because the user caught a real image breaking the rule. When a new note can be measured, it becomes a check here, so the user never has to give it twice. When only an eye can catch it (a skeleton shared with an approved layout, siblings in one category, a prop or a device, a starting price without "From"), it becomes a QA rule in `agents.md` (the V- and F-checks) instead. Every decision the renderer or `plan.mjs` can enforce also gets a case in the refusal suite (`scripts/test-refusals.mjs`, below), so a later change can't quietly undo it. Run the regression after every change.

## The Regression Test (Required After Every Change)

```bash
node <skill-dir>/scripts/test-examples.mjs                  # render every example, then run the refusal suite
node <skill-dir>/scripts/test-examples.mjs --refresh        # also re-render every approved reference image
node <skill-dir>/scripts/test-examples.mjs --examples-only  # the examples only, no refusal suite
node <skill-dir>/scripts/test-refusals.mjs [<filter>]       # the refusal suite alone (only the cases whose name contains <filter>)
```

- It renders all 54 `examples/*.json` (at least one per layout) into a temporary folder **without `--force`**, so every check that needs no history runs: retired layout, category, field and background (`FIELD FIT`, `BACKGROUND PICK`, `BACKGROUND CHECK`/`FIT`, `VIBRANT FIT`, `CHECKLIST FIELD`), heading, text, content, fairness, the logo checks and logo files. Most of the batch-5 examples carry the user's background pick (`"bgPick": true`), so the pick path is tested too. An example the rules refuse fails here, and a failing example means a change broke a layout. The real site history, the user's record and delivered images are never touched.
- Each example renders with its own empty history and ledger and an empty usage record (`FEATURED_USED_FILE`), so the result is the same on every run and the live site's used layouts never refuse a fixture (with a shared history, the renderer's "neighbours differ" background rule made the field depend on which parallel render finished first). Run `--refresh` twice and compare if you change the harness: the two runs must match exactly.
- The checks that need a history (`VARIETY`, `VIBRANT CHECK`, `SERIES`, `FINAL IMAGE LOCKED`) can't fire on an empty one: the refusal suite tests all four on its own temporary history and record; for any other history case, render against a copied history (`FEATURED_HISTORY_DIR`), never with `render.mjs --check-only`, which stops after the logo checks.
- `--refresh` rebuilds all 46 images in `references/approved/` from the example named in `references/approved/sources.json`. Run it whenever a rule changes how an approved layout looks, then compare old and new side by side: a difference you didn't intend is a regression (the swap labels drifted apart this way and were caught).
- A new approved image always gets an example spec and a line in `sources.json`, so it can never go stale.

### The refusal suite (`scripts/test-refusals.mjs`)

The user's decisions as 155 cases, each a small spec built from an `examples/*.json` with one change and the refusal it must get (or `OK`, it must render). `test-examples.mjs` runs it after the examples and fails if either part fails; `--examples-only` skips it. Every case runs on its own temporary site history (`FEATURED_HISTORY_DIR`), usage record (`FEATURED_USED_FILE`) and output folder, so the real history, the user's record and delivered images are never read or touched; a scenario runs its steps in order on one shared temp history (`plan.mjs` reservations, re-renders, other slugs). It prints a pass/fail table and exits 1 on any failure.

## Refusals (the renderer stops and says why)

The renderer checks in this order: retired layout, unknown mode or variant, missing category, `field` (`FIELD FIT`), `bgPick` (`BACKGROUND PICK`), `ranges` `"bare"` without the white pick (`BACKGROUND CHECK`), `bg` on a layout that paints its own canvas (`BACKGROUND CHECK`), the heading; then the logo checks (`LOGOTYPE`, `PILLS LOGO`, `CONNECT LOGO`, `TILES LOGO`, `SLASH NAME`, `GLASS LOGO`; `--check-only` stops here); then `CHECKLIST FIELD`, a `bg` that doesn't exist (`BACKGROUND CHECK`), `CONTENT`, `FAIRNESS`, `FINAL IMAGE LOCKED`, `VARIETY` (same topic, then the category and the site-wide cap), `VIBRANT CHECK`, `SERIES`, `VIBRANT FIT`, `BACKGROUND FIT`; and `TEXT` last, once the page is built. `LOGO FILE MISSING` fires wherever a local logo file is first read (in the logo checks, or when the page is built).

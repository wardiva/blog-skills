# Checks and Tests

Every check below exists because the user caught a real image breaking the rule. When a new note can be measured, it becomes a check here, so the user never has to give it twice. When only an eye can catch it (a skeleton shared with an approved layout, siblings in one category, a prop or a device, a starting price without "From"), it becomes a QA rule in `agents.md` (the V- and F-checks) instead. Run the regression after every change.

## The Regression Test (Required After Every Change)

```bash
node <skill-dir>/scripts/test-examples.mjs            # render every example with the current rules
node <skill-dir>/scripts/test-examples.mjs --refresh  # also re-render every approved reference image
```

- It renders all 48 `examples/*.json` (at least one per layout) into a temporary folder **without `--force`**, so every check that needs no history runs: retired layout, category, field and background (`FIELD FIT`, `BACKGROUND PICK`, `BACKGROUND CHECK`/`FIT`, `VIBRANT FIT`, `CHECKLIST FIELD`), heading, text, content, fairness, the logo checks and logo files. Most of the batch-5 examples carry the user's background pick (`"bgPick": true`), so the pick path is tested too. An example the rules refuse fails here, and a failing example means a change broke a layout. The real site history, the user's record and delivered images are never touched.
- Each example renders with its own empty history and ledger and an empty usage record (`FEATURED_USED_FILE`), so the result is the same on every run and the live site's used layouts never refuse a fixture (with a shared history, the renderer's "neighbours differ" background rule made the field depend on which parallel render finished first). Run `--refresh` twice and compare if you change the harness: the two runs must match exactly.
- The checks that need a history (`VARIETY`, `VIBRANT CHECK`, `SERIES`, `FINAL IMAGE LOCKED`) can't fire on an empty one: test them with a real render against a copied history (`FEATURED_HISTORY_DIR` pointing at a scratch copy), never with `render.mjs --check-only`, which stops after the logo checks.
- `--refresh` rebuilds all 40 images in `references/approved/` from the example named in `references/approved/sources.json`. Run it whenever a rule changes how an approved layout looks, then compare old and new side by side: a difference you didn't intend is a regression (the swap labels drifted apart this way and were caught).
- A new approved image always gets an example spec and a line in `sources.json`, so it can never go stale.

## Refusals (the renderer stops and says why)

The renderer checks in this order: retired layout, unknown mode or variant, missing category, `field` (`FIELD FIT`), `bgPick` (`BACKGROUND PICK`), `ranges` `"bare"` without the white pick (`BACKGROUND CHECK`), `bg` on a layout that paints its own canvas (`BACKGROUND CHECK`), the heading; then the logo checks (`LOGOTYPE`, `PILLS LOGO`, `CONNECT LOGO`, `TILES LOGO`, `SLASH NAME`, `GLASS LOGO`; `--check-only` stops here); then `CHECKLIST FIELD`, a `bg` that doesn't exist (`BACKGROUND CHECK`), `CONTENT`, `FAIRNESS`, `FINAL IMAGE LOCKED`, `VARIETY` (same topic, then the category and the site-wide cap), `VIBRANT CHECK`, `SERIES`, `VIBRANT FIT`, `BACKGROUND FIT`; and `TEXT` last, once the page is built. `LOGO FILE MISSING` fires wherever a local logo file is first read (in the logo checks, or when the page is built).

## Built-in Rules (applied automatically, no refusal)

| Rule | The feedback behind it |
| --- | --- |
| Every headline black `#0A0A0B` (white on the black and blue fields), hard-coded for every brand; a brand file's `headline` other than `#0A0A0B` is ignored with a warning | "Black, not blue", asked four times |
| Headline layouts (pills, connect, duo, dark) set every word in Inter 500 Medium | "Use same font weight 500 medium everywhere" |
| Connect headline on one line, centred above the divider, when it reads at 72px or more within 1080px wide; only a longer pair breaks onto two lines, within 900px, clear of the corner dot patches | "2 lines look visually off"; at 1200px wide it ran past x 210–1390 (QA, batch 5) |
| Stat number capped at 150px; the card grows to match; no gap for an empty card heading | "4–9% too big, illustration too small" |
| Receipt headline semibold, at most 84px | "The heading makes the balance off" |
| Swap: both text labels share one size | Same role, same form (taste 2; caught by the regression) |
| Edge-only patterns (`shortlist` "+" grid, `lineup` dots) are masked clear behind the content (`GL_EDGE_MASK`); `versus/slash` masks its dot grid on black the same way | "Too dark, light it, not in the whole image"; then "not visible"; "should not be in all area" |
| Dot grids, rings and patterns stay sparse and faint, never dense or dark; `versus/bento` has none | "Pattern is too much"; "delete pattern from bg" (bento) |
| Dark: text at x 120; the product's icon in `#0A0A0B` on a white tile top-left | "Left padding is too much"; "should be the product's logo" |
| Pills: flat outer cuts, tips 112px apart, subtle gradient + noise | The user's reference, measured |
| Slash names keep their auto-fit size. The two-tone split: several words colour the last word, on its own line; one word splits at its last capital break (AdvancedMD → Advanced + MD) or before its digits; a hand-marked `{{ }}` must leave some white (otherwise `SLASH NAME CHECK FAILED`) | "Perfect", never enlarge; "two colours, one white compulsory" |
| No shadows on blue or black fields | Shadows looked heavy on vibrant fields |
| Frost: each mark fills 48% of its glass tile (was 60%) | "The icons are too big and this is why visual balance off, improve" |
| The user's background pick (`"bg": "<field>", "bgPick": true`) skips the fit lists and the canvas refusal; a canvas drawn through the shared Gumloop canvas drops away so the picked field shows; the history records the picked field and `bgPick: true`, and the render line says `bg=<field> (picked)` | "show me 12 images and options for backgrounds and i'll select the bg for each" |
| Per-card `scale` for a wide or thin mark: `lineup` 0.5–0.8 of the tile (default 0.7), `hub` logos only 0.5–0.8, `versus/center` sides 0.45–0.8 (default 0.66) | NextGen's wave, Phreesia's and Klara's wordmarks looked lighter than their neighbours (QA, batch 5) |
| `prompt` rows with a `logo` show the brand's real mark in their tile; a chip is `{logo, label}` or logo-only `{logo}` (the wordmark, 40px tall). A panel of two rows or fewer grows them (bigger marks) to fill it; `"panel": {"even": true}` keeps every row at full strength (no fade) for rows that are equals | File icons beside product names read as files (QA, batch 5); a half-empty panel read as a missing row (Visual QA, b10); RXNT vs DrFirst as two big logo rows, approved (image 48) after `versus/plans` was retired |
| `ranges` and `versus/lanes`: every light grey track sits on a white card, except `ranges` `"bare": true` on the picked white field, which drops the card and darkens the tracks a step (`#E1E5EC`); on `ranges` an open "From" price (`"open": true`) is a bar that fades upward with no solid end, and one price is a dot | "Every bar end reads as a figure" (Fact QA, b8); light grey tracks need a white card behind them (Visual QA, b8); bare: "use the previous bg, and in that dont add container for bars section" |
| `versus/badges` options: `nameSize`, `nameWeight`, `nameInk` cap the names, `valueSize` caps the figures, `spread: true` moves the sides out and centres the "vs" between the value boxes (approved: 44, 600, 84, spread); without them, the original look | "the heading of theranest and valant are too bold and big, visual hierrachy is not good and balanced" |
| `versus/checks` options: `"checks": false` drops the blue check boxes; with it, `"big": true` grows the logo tiles (104, mark 72) and the row spacing | "checkboxes are not needed" (AAPC Codify vs Find-A-Code) |
| `versus/connect` option: `"cornerDots": false` drops the dot patches in the top corners | "delete these dot grid from top left and top right" |
| `lineup` takes 3–7 logos (one row) | Pediatric EHR (7 picks) moved from the retired `grid` to the lineup: "for this use this glass version template" |

## Planning Tools

| Tool | Use |
| --- | --- |
| `scripts/logo-check.mjs <domains>` | Before reserving pills, connect, glass, tiles or logotype: which layouts each brand's logos allow (same checks as the renderer) |
| `scripts/plan.mjs` | Per category: "Not used yet (first in line)", "Used only in other categories", "Not again in <category>"; reserves one category's articles with `--reserve <slug>=<mode>[/<variant>][!][@<topic>] ...` (`!` = the user's pick for that slug); `--release <slug> ...` drops unrendered reservations. Refuses with "PLAN REFUSED" or "RELEASE REFUSED" (nothing written) |
| `scripts/usage.mjs` | The shared usage rule for render.mjs and plan.mjs (SKILL.md §3): the site history, the user's brand-scoped record, normalised categories, and the lock that parallel renders, plans and finalizes share. A layout's own `asOf` in the record overrides `recordedAt` as its cutoff (history up to `asOf` is covered by the record, later renders count again). Prints "USED-LAYOUTS WARNING" for record entries it can't apply as written |
| `references/used-layouts.json` | The user's own record, kept on the Template Usage page (https://claude.ai/artifact/8wxx5rif2nNTk81bzgaQ6q), for one brand (`"brand"`), the truth as of its `recordedAt` (or a layout's own `asOf`, set when the user changes one layout in chat, e.g. `versus/scores` back to "unused": "add that to not used cus i love the design"). Sync it as in SKILL.md, Workflow step 2, then push |
| `scripts/sheet.mjs` | QA contact sheet of the whole site (or one category); `--highlight <slug1>,<slug2>` frames the batch. The user sees every image together, so a look-alike anywhere is visible |
| `scripts/finalize.mjs` | Locks delivered images and stores a copy |
| `scripts/bgpick.mjs` | The background picker (SKILL.md Workflow step 6): `render` renders each spec on every field its layout takes as a pick (`render.mjs --pick-fields`; a layout that refuses one gets `default`, its own canvas; `ranges` `"bare"` gets `white` only) into `featured-images/_previews/bg/<slug>-<field>/img/`, 4 at a time, each with a temporary copy of the site history and the folder's ledger; `page` builds the picker page (thumbnails in `bg/` next to it; picks save to a db collection, one doc per image: `{bg, note, at}`); `apply --picks` writes `"bg"` + `"bgPick": true` into each spec, keeping its formatting (a one-line spec stays on one line), and refuses a field the layout can't take (`default`, the layout's own background, is always accepted) |
| `scripts/test-examples.mjs` | The regression above |
